# Student guide

Work week by week on the Sunday–Thursday schedule in each assignment (approximately 40 hours in an ordinary week). You own the environment: start it, verify it, create visible cases, reset it, and diagnose ordinary failures yourself. This operational work is part of learning engineering systems; PowerShell or Windows expertise is not being assessed. Do not open the mentor directory. Keep your implementation in a separate Git repository or a `student-work` folder excluded from clean/reset operations. For every week submit: source, automated tests, `DECISIONS.md`, `RUNBOOK.md`, and a short evidence file containing commands and results. Never include secrets or private production data.

Before each exercise, start and smoke-test its environment. Use `training-platform\student\run-case.ps1` for visible cases and `new-case.ps1` to design your own. When a behavior surprises you, record the observation, hypothesis, experiment, and result. Before asking the mentor, complete the troubleshooting checklist in the weekly assignment. The review rewards sound reasoning more than accidental success.
